# E19: recovering the missing Nutrition5k coverage (Task P19)

**Status: COMPLETE.** Both nerfacto and BioNeRF now cover **3,521 of 3,522**
scenes. E18's coverage bias is eliminated and E9's "common-coverage
subpopulation" caveat is withdrawn.

## What was actually wrong

E18 established that the missing per-scene logs were *not* missing at random,
but not why. The cluster job logs answer it: the April/May evaluation sweeps
show **66 CANCELLED and 63 DUE TO TIME LIMIT** against only 25 tracebacks. The
jobs were killed by the Slurm 5-hour wall clock partway through each node's
chunk. Training had finished; `ns-eval` simply never reached the tail.

So the checkpoints still existed. The gap was an evaluation gap, not a
training gap - which meant it could be closed by evaluation alone.

| | missing | had a surviving final checkpoint | needed training |
|---|---|---|---|
| BioNeRF | 1,001 | **997** | 4 |
| nerfacto | 559 | **385** | 174 |

Recovering 1,382 scenes by evaluation instead of retraining saved roughly
690 GPU-hours (~1 month on the two available cards); the actual cost was about
a day.

## How it was done

All checkpoints, plus the cluster's own `bionerf.sif` container, were copied
off the cluster first (116 GB, verified complete, zero corrupt files).
Evaluating BioNeRF inside its original container means the recovered rows come
from the same training run as the existing ones rather than a reimplementation.

- BioNeRF: `step-000025999` (uniform across all 1,444 surviving checkpoints),
  evaluated in `bionerf.sif`. Split across two GPUs; the second machine
  streams each scene (ship -> evaluate -> delete) because it has only 13 GB
  free, so nothing accumulates there.
- nerfacto: `step-000029999` only. The recovered tree also holds intermediate
  checkpoints (2k, 4k, 14k, 22k) from interrupted runs, which are **not**
  comparable with the 30k reference and were filtered out.

## Validation gate

Scenes that already had a reference row were re-evaluated and compared before
anything was merged. **10/10 reproduced exactly**: PSNR delta 0.0000, SSIM
0.00000, LPIPS <= 1.6e-4 (VGG non-determinism, consistently positive, ~60x
inside the 0.01 tolerance). The same check passed independently on both
machines, and it also demonstrated empirically that `num_rays_per_chunk` is
output-invariant - a 2048-chunk run reproduced a 32768-chunk reference - though
the production runs use the cluster's own 32768 anyway, so the recovered rows
carry **zero configuration deviation**.

The nerfacto path needed no separate gate: its recipe was already validated
against cluster metrics to 3e-4 dB on cluster-trained checkpoints, which is
exactly this path.

## Provenance, recorded per row

- `recovered-P19` (997 BioNeRF, 385 nerfacto): original cluster weights,
  re-evaluated. Same training run as the released table.
- `retrained-P19` (3 BioNeRF, 173 nerfacto): no checkpoint survived, so these
  are **new** training runs - same config and seed, different weights.

## The one permanent exclusion

`dish_1563900172` is uncoverable for both methods. Its source image
`images/0006.png` is a truncated PNG (18,432 bytes; `libpng` read error,
`cv2.imread` returns `None`). `colmap2nerf` computes per-image sharpness over
every registered view, so the corrupt frame aborts `transforms.json`
generation and no training or evaluation run is possible. The cluster never
produced a checkpoint for it either, for the same reason. Impact: 1 scene of
3,522 (0.03%).

## Effect on E9 - unfavourable, and that is the point

I4 and I5 both become **3,473**, the full cross-method intersection, identical
to E1's population. The subpopulation restriction is gone.

| | before (I4=2,915 / I5=2,228) | after (I4=I5=3,473) |
|---|---|---|
| 4-method, 72 scenes | LCB 0.105 | LCB 0.0700 |
| 4-method, 96 scenes | - | **LCB 0.1116** |
| 4-method, 120 scenes | - | LCB 0.2007 |
| 5-method, 120 scenes | LCB 0.148 | **LCB 0.1027** |

The frontier moved **against us**: the 4-method 0.08 target now needs 96 scenes
rather than 72. That is the direct confirmation of E18's prediction - the
previously covered scenes were systematically easier, so the old E9 numbers
were flattered by the missingness. The completed audit is harder but valid for
the whole benchmark instead of a subpopulation, which is the stronger claim.

RASS-96 **passes** the 4-method joint event on the full I4 (94/96 scenes in
intersection, no violations). It fails the 5-method event on I5
(`bionerf.ssim`, `bionerf.lpips`). RASS-48 fails both.
